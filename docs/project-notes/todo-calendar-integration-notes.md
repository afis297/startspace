# Связь задач и календаря

**Статус:** актуальная тематическая заметка, 16 августа 2026.
**Основная реализация:** [`src/widgets/basic-definitions.js`](../../src/widgets/basic-definitions.js).

## Модель данных

Задача хранится в `todo.config.tasks` в формате:

```js
{
  id: "uuid",
  text: "Текст задачи",
  done: false,
  dueDate: "YYYY-MM-DD"
}
```

Срок является обязательным в рабочей модели. Новая задача получает дату текущего дня по умолчанию. При первом обновлении старого To‑Do виджета все сохранённые задачи без корректного `dueDate` нормализуются на текущую дату через событие `todo-migrate-missing-dates`.

> В интерфейсе всё ещё доступна команда «Без даты» кастомного выбора даты, но после следующей нормализации задача снова получит текущий срок. Для устойчивой модели задача должна иметь корректную дату `YYYY-MM-DD`.

## Отображение и редактирование срока

Срок показывается в компактном поле `ДД.ММ.ГГГГ` внутри той же строки, что номер, чекбокс, текст задачи и удаление. Рядом остаётся кнопка календаря. Нажатие открывает кастомный выбор даты поверх рабочего стола: он переносится в `document.body` и получает высокий слой, поэтому не раздувает список задач и не обрезается его прокруткой.

| Сценарий | Событие Store | Результат |
|---|---|---|
| Добавление задачи | `todo-add` | Сохраняется задача с выбранным сроком; после добавления выбор срока возвращается к текущей дате. |
| Редактирование срока | `todo-date` | Обновляется `dueDate` одной конкретной задачи. |
| Выполнение задачи | `todo-toggle` | Меняется `done`; задача сохраняет срок и продолжает участвовать в календарной модели. |
| Удаление задачи | `todo-remove` | Задача исчезает из To‑Do и из отметок календаря. |
| Миграция старых данных | `todo-migrate-missing-dates` | Пустой или неверный срок заменяется текущей датой. |

## Синхронизация с календарём

Обычный виджет `calendar` собирает задачи всех экземпляров `todo` через `plannedTasks(context)`. Для каждого дня текущего месяца он проверяет задачи с равным `dueDate` и:

1. добавляет классу дня `is-scheduled`;
2. показывает до трёх маркеров задач и счётчик для оставшихся;
3. добавляет названия задач в `title` и `aria-label`;
4. обновляет сетку после любых изменений To‑Do.

Текущий календарь всегда строит фиксированную шестинедельную сетку из 42 ячеек. Удалённый тип `daily-calendar` не используется и миграционно отбрасывается.

## Проверенный сценарий

В живом предпросмотре подтверждено следующее: две существующие задачи без срока были нормализованы на `16.08.2026`; эта дата показывается в строках задач и в форме добавления; день 16 в обычном календаре получает маркер запланированной задачи. После закрытия календаря выбора срока размеры списка остаются неизменными: ложная горизонтальная и вертикальная прокрутка не создаётся.

## Ограничение

Все To‑Do виджеты сейчас питают один календарный контекст. Если в будущем появятся независимые области планирования, потребуется явное поле связи, например `calendarId`, и миграция существующих задач.
