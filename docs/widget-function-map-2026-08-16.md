# Карта функций и архитектуры виджетов

**Проект:** My Free Layout Tab
**Дата анализа:** 16 августа 2026
**Назначение документа:** рабочая карта кода, по которой можно менять или расширять виджеты без повторного объяснения их базовой логики.

> Каждый виджет — это не самостоятельная страница, а экземпляр в общем `store`. Его декларация определяет начальные данные и доступные свойства; интерфейс создаётся один раз функцией `create`, после чего синхронизируется функцией `update`.

## 1. Как устроено приложение

| Слой | Ответственность | Главные точки кода |
|---|---|---|
| Запуск | Создаёт реестр, загружает сохранённое состояние, добавляет стартовые виджеты и монтирует UI | `src/app/bootstrap.js` |
| Состояние | Хранит виджеты, глобальные настройки и порядок слоёв; рассылает события подписчикам | `src/app/store.js` |
| Реестр | Валидирует определения, создаёт новый экземпляр и объединяет общие/локальные свойства | `src/widgets/registry.js` |
| Рабочая область | Создаёт DOM, вызывает `create`/`update`, применяет стили, двигает и масштабирует виджеты | `src/ui/workspace.js` |
| Свойства | Рендерит поля по декларации виджета и пишет изменения в `root`, `style` или `config` | `src/ui/properties-panel.js` |
| Нижняя панель | Открывает каталог, запрашивает разрешения, добавляет и возвращает свёрнутые виджеты | `src/ui/dock.js` |
| Хранение | Сохраняет снапшот в `chrome.storage.local`; вне Chrome использует `localStorage`; мигрирует старые форматы | `src/app/persistence.js` |

### 1.1. Жизненный цикл одного виджета

```text
Каталог / стартовый макет
        ↓
registry.createWidget(type)
        ↓
store.addWidget(instance)
        ↓
workspace.renderWidget(instance)
        ↓
definition.create(instance, context)  — один раз создаёт DOM
        ↓
definition.update(root, instance, context) — обновляет данные при каждом значимом событии
        ↓
patchConfig / store.updateWidget
        ↓
store.subscribe → workspace / panels / persistence
```

Экземпляр имеет общую форму:

```js
{
  id, type, title,
  position: { x, y },
  size: { w, h },
  zIndex,
  collapsed,
  style: { /* оформление */ },
  config: { /* функциональные данные конкретного виджета */ }
}
```

`style` отвечает только за оформление и масштаб, а `config` — за содержание, режим работы, результаты вычислений и пользовательские данные. Функция `patchConfig(context, id, patch)` безопасно объединяет частичное изменение с текущим `config`, не уничтожая остальные поля.

## 2. Базовые правила разработки виджетов

| Правило | Реализация | Практическое следствие |
|---|---|---|
| Создание DOM отдельно от обновления | Обязательные `create` и `update` проверяются реестром | Не пересоздавайте весь виджет при каждом вводе, если можно обновить конкретный элемент. |
| Обновления через Store | `patchConfig`, `patchWidget`, `store.updateWidget` | Нельзя менять сохранённые данные только в DOM: иначе изменения потеряются после следующего рендера. |
| Асинхронность защищена | `beginRequest` и `isCurrentRequest` | Ответ старого запроса не должен перезаписывать более новый результат. |
| Таймеры очищаются | `disposeTimer`, `disposePlayer`, `disposeSnake`, `disposeRest` | Любой `setInterval` обязан очищаться при удалении/пересоздании виджета. |
| Ввод сохраняет фокус | `workspace` не вызывает `update`, пока фокус в текстовом редакторе активного виджета | При добавлении полей ввода не нужно вручную блокировать каждый рендер. |
| Внешние ссылки безопасны | `safeUrl`, `openSafeLink`; для аудио — проверка HTTPS | URL нормализуются до открытия или сохранения. |

## 3. Общие свойства и их реальное действие

Общие свойства добавляет `registry.propertiesFor(widget)`. У большинства типов они показываются автоматически, кроме явно исключённых в `excludedCommonProperties`.

| Группа | Поля | Как применяется |
|---|---|---|
| Поверхность | Материал, прозрачность, фон, блюр, тень | `workspace` устанавливает CSS-переменные `--widget-surface-*`, `--widget-blur`, `--widget-shadow`. |
| Граница | Тематический акцент, свой акцент, цвет/толщина границы, скругление | Свой акцент автоматически выключает `useThemeAccent`; глобальный переключатель углов приоритетнее локального радиуса. |
| Текст | Цвет, размер текста, насыщенность, выравнивание | `--widget-font-scale`, `--widget-font-weight`, `--widget-content-align`; для переработанных виджетов размеры дополнительно привязаны к `--widget-font-scale`. |
| Масштаб | Автомасштабирование, ручной масштаб интерфейса | Вычисляется из фактического и базового размера виджета; влияет на внутренний `widget-scale-layer`, а не на рамку. |
| Макет | Отступы, контраст и цвета заголовка | Передаются в CSS-переменные рабочего контейнера. |

> Глобальные углы работают так: при `settings.behavior.roundedCorners === false` рабочая область записывает `--widget-radius: 0px`; в противном случае использует `var(--radius-md)`. Поэтому калькулятор, задачи, ссылки и календарь должны использовать переменную радиуса, а не литеральные значения в пикселях.

## 4. Каталог виджетов и их функции

### 4.1. Основные и продуктивные виджеты

| Тип | Что хранит в `config` | Действия пользователя | Важные связи/ограничения |
|---|---|---|---|
| `clock` | `format`, `showSeconds`, `clockScale` | Выбор 12/24-часового формата, секунды, размер времени | Таймер раз в секунду; очищается через `disposeTimer`. |
| `note` | `content` | Ввод текста заметки | Сохраняет текст на каждый `input`; в DOM не перезаписывает активное поле. |
| `todo` | `tasks[]`: `id`, `text`, `done`, `dueDate` | Добавление, завершение, удаление и смена срока | Срок выбирается `createDatePicker`; задача с `dueDate` отмечается в обычном календаре. |
| `link` | `text`, `url`, `icon` | Открывает настроенный URL | Адрес открывается через безопасный helper. |
| `quote` | `index` | Переключение фразы | При первом создании продвигает индекс в очереди цитат. |
| `bookmarks` | `linksText`, `links`, `showDomain` | Только открытие сохранённой ссылки | Добавление/изменение выполняется исключительно через свойства; старый стандартный набор миграционно скрывается. |
| `today-tasks` | `followCalendar`, `date`, `tasksByDate` | Список задач для выбранного дня, Google Tasks, переход к календарю | **Устаревшая связь:** ищет `daily-calendar`, который удалён из реестра. В текущем коде режим `followCalendar` и кнопка перехода фактически не найдут календарь. |

### 4.2. Календарь и задачи: действующая связь

Обычный `calendar` в `updateCalendar` собирает **все** `todo`-виджеты из состояния. Берутся только задачи с корректным `dueDate` формата `YYYY-MM-DD`. Для каждой из 42 ячеек месяца создаются:

1. Номер дня.
2. Класс `is-scheduled`, если есть хотя бы одна задача.
3. До трёх статусных маркеров `calendar-task-pip`; для большего числа — счётчик `+N`.
4. `title` и доступное `aria-label` с названиями задач.

После любого события у виджета `todo` рабочая область принудительно повторно вызывает рендер всех `calendar`. Это неявная, но корректная связь: добавление, смена даты, завершение или удаление задачи сразу отражается без отдельного события календаря.

### 4.3. Время, расчёты и игры

| Тип | Модель данных и действия | Технические особенности |
|---|---|---|
| `countdown` («Обратный отсчёт») | `label`, `target`; показывает остаток до даты | Синхронизируется с границей минуты и никогда не показывает отрицательное значение. |
| `timer` («Секундомер») | `running`, `elapsedMs`, `startedAt`; старт/пауза/сброс | При паузе накопляет пройденное время; при работе обновляет только значение один раз в секунду. |
| `focus-timer` («Таймер») | `totalSeconds`, `remainingSeconds`, `running`, `endsAt`; пресеты 5/15/25/45 минут, ручная установка, старт/пауза, +1 минута и сброс | Хранит абсолютное время завершения, поэтому корректно переживает повторное открытие вкладки. При истечении автоматически останавливается и освобождает интервал. |
| `random` | `min`, `max`, `result` | Округляет границы, нормализует их порядок, сохраняет результат. |
| `calculator` | `expression`, `result` | Собственный парсер без `eval`: только цифры, арифметика и скобки, не более 120 символов. Поддерживает клавиатуру, курсор, Enter, Escape/C, Backspace, `, × ÷`. |
| `game` (2048) | `board[16]`, `score` | Поле получает фокус только при наведении/нажатии; стрелки не вмешиваются в страницу. Мигрированная игра инициализируется один раз. |
| `snake` | Координаты змейки/еды, направление, очки, рекорд, скорость, статус | 12×12; тики только при `playing`; запрещает разворот на 180°, отслеживает столкновения и очищает интервал при остановке. |

### 4.4. Медиа и благополучие

| Тип | Возможности | Ограничения и очистка |
|---|---|---|
| `player` | Прямое аудио: play/pause, ±10 секунд, шкала, Media Session; YouTube: безопасно открывает официальный URL; умеет найти звучащую вкладку | YouTube не воспроизводится во встроенном `<audio>`. Управление внешней вкладкой зависит от разрешений Chrome. При удалении останавливает audio, очищает source и ссылку. |
| `rest` | Встроенные атмосферные записи/свой HTTPS-поток, громкость до 1.5 через Web Audio Gain, 25-минутный таймер сна | Усиление запускается только когда Web Audio доступен. При удалении останавливает запись, таймер и закрывает AudioContext. |

### 4.5. Сетевые и поисковые виджеты

| Тип | Сервис | Данные и защита |
|---|---|---|
| `weather` | Open-Meteo: геокодирование + текущая погода | По городу или координатам. Обновляет каждые 15/30/60 минут; сохраняет последний результат и время; отменяет логически устаревшие ответы через номер запроса. |
| `currency` | ExchangeRate API | Конвертирует сумму, меняет валюты местами, поддерживает автообновление. При смене пары сбрасывает кэш отображения и повышает номер запроса. |

| `search` | Google, Яндекс, DuckDuckGo, Bing, Brave | Глобально выбирается движок и открытие в новой вкладке; локально можно переопределить только способ открытия. Сознательно исключён общий `fontScale`. |

## 5. Внешние данные, разрешения и устойчивость

| Сценарий | Где контролируется | Что нельзя предполагать при изменении |
|---|---|---|
| Добавление виджета с сетью | `dock` → `requestWidgetPermissions` | Виджет может не быть создан, если пользователь не выдал origin-разрешение. |
| Погода | `data-services.getWeather` | Город сначала геокодируется; результаты могут быть помечены `stale` из кеша. |
| Валюта | `data-services.getExchangeRate` | Ошибкой считается неподдерживаемая валюта; одинаковые валюты возвращают курс 1 без запроса. |
| Перевод | `data-services.translateText` | Лимит MyMemory — 500 байт UTF-8; 429 преобразуется в понятное сообщение о дневном лимите. |
| Аудио | `playerSource`, `safeAudioUrl` | Внешний поток отдыха должен быть HTTPS; проигрыватель YouTube открывает веб-сайт, а не stream. |

## 6. Хранение, миграции и импорт

Текущее состояние хранится под ключом `layoutStateV5`. В расширении это `chrome.storage.local`; в обычной браузерной версии — `localStorage` с префиксом `mflt:`. Сохранение отложено на 450 мс и выполняется для всех событий, кроме простого вывода виджета на передний план.

При миграции нормализуются:

- старые алиасы типов (`game2048 → game`, `links → link`, `tasks → todo`, `clocks → clock`);
- позиция и размер из нескольких возможных старых полей;
- общие `style`-поля и настройки поведения;
- удалённые типы `daily-calendar` и `today-tasks` — они отбрасываются и при миграции, и при загрузке V5.

**Следствие:** сохранять `daily-calendar` обратно или использовать его как живую зависимость нельзя. Виджет `today-tasks` удалён из каталога, исходников и загружаемых макетов. Планирование задач выполняется только через основной тип `todo` и его модель `todo.tasks`.

## 7. Известные технические долги и безопасные направления развития

| Приоритет | Наблюдение | Рекомендованное действие |
|---|---|---|
| Средний | Виджеты внешних данных запрашивают разрешение только при добавлении из каталога. | Добавить действие повторного запроса разрешения по пользовательскому нажатию для импортированных, восстановленных и ранее отклонённых виджетов. |
| Средний | Некоторые компактные CSS-шрифты и внутренние элементы используют явные размеры. | Для каждого нового внутреннего элемента использовать `var(--widget-font-scale, 1)` и `var(--widget-radius)`. |
| Средний | Все виджеты типа `todo` участвуют в общем календаре. | При появлении нескольких независимых рабочих пространств/календарей добавить явный `calendarId` или область задач. |
| Средний | `design-polish.css` использует значительный слой поздних правил с `!important`. | Поэтапно переносить финальные правила в базовые стили и удалять заменённые переопределения. |
| Низкий | `quote` изменяет индекс при каждой новой загрузке страницы. | Оставить как текущий эффект «цитата дня» или ввести настройку автообновления. |

## 8. Практический чек-лист перед изменением виджета

1. Найти тип в `src/widgets/*-definition.js` и проверить `defaultConfig`, `properties`, `create`, `update`, `dispose`.
2. Решить, является ли новое значение функциональным (`config`) или оформительским (`style`).
3. Записывать изменения только через `patchConfig`, `patchWidget` или `store.updateWidget`.
4. При добавлении таймера, audio или подписки добавить очистку в `dispose`.
5. Если виджет использует сеть — применить `beginRequest/isCurrentRequest` и продумать ошибку, кеш и разрешение.
6. Если элемент имеет явные размеры текста/углов — связать его с `--widget-font-scale` и `--widget-radius`.
7. Для связи между виджетами убедиться, что тип существует после миграции; не зависеть от `daily-calendar`.
8. Проверить обычное состояние, пустое состояние, узкий размер, квадратные углы, изменённый текстовый масштаб и перезагрузку сохранённого макета.

## 10. Актуализация после редизайна задач и панелей

### 10.1. Срок задачи — обязательное рабочее поле

Новая задача создаётся со сроком текущего дня. В `updateTodo` старые задачи без корректного `dueDate` получают срок текущего дня через патч `todo-migrate-missing-dates`, после чего выполняется повторный рендер. Это гарантирует, что компактное поле даты не остаётся пустым и что календарь получает все сохранённые задачи.

Поле срока показывает `ДД.ММ.ГГГГ` рядом с кнопкой календаря. Его ширину нельзя обнулять или заменять только иконкой: значение является обязательной частью строки задачи. Закрытый `.date-picker-popover` должен иметь `display: none`; иначе, будучи возвращённым внутрь To‑Do, он увеличивает вычисленные `scrollWidth` и `scrollHeight` списка. При открытии popover переносится в `document.body` и получает высокий слой.

### 10.2. Быстрые ссылки

`bookmarks.defaultConfig` начинается с пустого `links`. Старый набор Google, YouTube, GitHub и Google Calendar распознаётся как legacy-набор и не отображается. Единственный редактор ссылок — свойство `linksText`; рабочий виджет не содержит форму добавления или удаления.

### 10.3. Внешний вид и меню

Пользовательский акцент имеет явный приоритет: выбор цвета автоматически снимает `useThemeAccent`. В `green-console` внутренние элементы сложных виджетов используют `--widget-user-*` как пользовательские значения и тему лишь как fallback. Углы новых компонентов обязаны зависеть от `--widget-radius`, а их текст — от `--widget-font-scale`.

Кастомные `select-menu` и открытые календари срока работают как портальные элементы: они располагаются поверх интерфейса вне прокручиваемых контейнеров. Для новых контролов следует повторять эту модель, а не повышать `z-index` внутри родителя с `overflow`.


### 10.4. Каталог добавления виджетов

Каталог `.widget-picker` использует общий контроллер `mountFloatingPanel` с ключом `settings.panels.widgetPicker`. Заголовок с `data-role="panel-drag"` перемещает панель, а кнопка `data-action="resize-panel"` в правом нижнем углу изменяет ширину и высоту. Геометрия `{ x, y, w, h }` ограничивается размерами окна, сохраняется через `store.updateSettings` после отпускания указателя и автоматически нормализуется при изменении размера вкладки.

Не следует применять перемещение к кнопке закрытия, полям ввода, ссылкам или карточкам виджетов: контроллер считает их интерактивными элементами и не начинает перенос. Плавающий каталог располагается выше dock, но ниже портальных меню и календарей, поэтому выпадающие списки сохраняют приоритет поверх панели.


### 10.5. Задачи на текущем дне календаря

Каждая дата с задачами получает класс `is-scheduled`, набор статусных точек `calendar-task-pips` и явный `calendar-task-count` в правом верхнем углу. Счётчик показывает до `9+` задач и имеет самостоятельный контрастный стиль. Для сегодняшнего дня он становится тёмным с неоновым текстом, поэтому не сливается с ярким выделением самой даты в `green-console`. Полные названия задач по-прежнему доступны в `title` и `aria-label` ячейки календаря.


### 10.6. Управление воспроизведением во вкладках

Виджет `browser-media` запускает поиск только по явному нажатию «Найти воспроизведение». В этот момент он запрашивает необязательные разрешения `tabs`, `scripting` и доступ к веб-страницам, после чего ищет вкладки Chrome с активным аудио и обращается только к обычным HTML-элементам `<audio>` и `<video>`. Доступ не запрашивается при установке расширения и не используется для фонового опроса.[1]

После обнаружения виджет может поставить HTML-медиа на паузу/продолжить, перейти на ±10 секунд, изменить громкость самого HTML-плеера, выключить звук вкладки и активировать её. Страницы Chrome, системные страницы, защищённые плееры и сайты без обычного HTML-медиа могут отказать во внедрении; в таком случае виджет сообщает об ограничении и не выполняет скрытых обходов. Доступ к `title` вкладки и программное внедрение требуют соответствующего разрешения на вкладки и URL.[2]

### 10.7. Материал и прозрачность виджета

`workspace` передаёт выбранный `surfaceMode` через `data-surface` и вычисляет `--widget-surface-alpha` из настройки непрозрачности. Режим `solid` всегда принудительно использует 100% альфа-канал как для тела, так и для шапки виджета; режимы `soft`, `glass`, `acrylic`, `clear` и `custom` сохраняют установленную пользователем прозрачность.

Тема `green-console` отвечает только за консольные цветовые переменные, рамку и текст. Она не должна задавать собственный `background` для `.desktop-widget`: фон остаётся в `widgets.css`, где различаются все шесть материалов. Это правило защищает виджет от повторного слияния прозрачных и непрозрачных режимов.
