# Дизайн-стандарт Startspace

Живые правила оформления. История проверок — в [`archive/`](./archive/README.md); при конфликте побеждает код.

## Токены

| Токен | Роль |
|---|---|
| `--bg-0`, `--bg-1` | Фон и глубина рабочего стола, не фон активных контролов. |
| `--surface`, `--surface-strong` | Карточки и панели; карточка светлее фона на 1–2 ступени, а не только рамкой. |
| `--text` | Обычный текст, никогда не приглушать прозрачностью. |
| `--muted` | Только вторичное: домены, статусы, подсказки. Не для обязательных полей. |
| `--accent` | Точка внимания: primary-action, выбранное состояние, ключевое число. Не более 1–2 на область. |
| `--accent-contrast` | Текст на акценте. |
| `--danger` | Только рисковые/необратимые действия. |
| `--widget-user-*` | Пользовательские цвета поверх темы; жёсткие цвета темы вместо переменных виджета запрещены. |

Контраст обычного текста — минимум **4.5:1**, крупного — **3:1** (проверяет `theme-contrast-smoke`). Интерактивные цели — минимум **24px** или с зазором (проверяет `menu-accessibility-smoke`).

## Тип и сетка

Шкала: **12px** метаданные, **14–15px** текст и контролы, **18–20px** заголовки, **32–40px** ключевой показатель. Внутренние отступы карточек 16–20px, зазоры между ними 16–24px.

Привязка к сетке: `settings.behavior.gridSize`, по умолчанию **12px**, регулируется в настройках (4–32). Не сдвигать чужие виджеты без явного действия пользователя.

## Радиус

Один глобальный радиус: `behavior.cornerRadius` (по умолчанию 8, `0` при выключенных скруглениях) → `--widget-radius` на каждой карточке (`src/ui/workspace.js`). Пер-виджетного радиуса нет и не добавлять.

## Каскад

| Уровень | Файл | Что класть |
|---|---|---|
| Токены | `tokens.css`, `themes/presets.js` | Цвета, радиусы, шкала, отступы, скорости анимаций. |
| Каркас | `layout.css` | Стол, dock, панели, каталог, адаптивность. |
| Виджеты | `widgets.css` | База карточки, заголовок, действия, поля, состояния. |
| Специфика | Секция с префиксом виджета | Только особенности сценария, не переопределение каркаса. |

`design-polish.css` — слой поздних переопределений; новые правила писать в их уровень выше, а не добавлять туда очередной override. Перед новым эффектом ответить: какую задачу пользователя поддерживает, какой уровень иерархии выражает, не дублирует ли существующий сигнал. Нет ответа — эффект не добавляется.

## Чек-лист правки

Не более 1–2 сильных акцентов на экран; у каждого цвета есть роль; редкие и разрушительные действия раскрываются по запросу; focus видим; шаблоны применяются только при первом запуске или явно; изменение опирается на токены.
